## 上下文

AIOps 后端在流式传输其 LangGraph Planner、Executor、Replanner 和 Report 节点之前会保留经过身份验证的诊断任务。该流使用通用的 SSE 联合体，后端之后可以返回包含步骤、工具调用审计、引用、报告、证据链接和 checkpoint 的证据链。前端的 `/aiops` 路由当前是占位符。

## Goals / Non-Goals

**目标：**
- 为操作员提供一个简洁的诊断入口，用于自然语言的事件问题和可选的结构化警报上下文。
- 在流处于活动状态时，仅渲染后端提供的任务进度、工具、引用、错误和报告。
- 让操作员选择持久化的历史记录，并在运行后检查完整的证据链。
- 通过从经过身份验证的后端 APIs 派生每个显示来保留 user ownership 边界。

**非目标：**
- 构建告警接收/订阅、任务取消、手动图编辑或仅限浏览器的诊断执行器。
- 修改 LangGraph 规划、MCP 行为、报告生成、证据持久化或共享事件模式。

## 决策

### 专用的 AIOps 客户端和存储
使用从已建立的通用 HTTP 和 SSE 客户端构建的专用 `aiopsClient`，加上一个聚焦的 Pinia 存储。它负责历史记录、活动证据链、流式事件时间线和运行状态。拒绝重用遗留的受保护数据状态，因为它无法对诊断进行建模，并会将不相关的工作区绑定在一起。

### 后端事件是实时的真相来源
UI 仅从 `task.status`、`tool.call`、`reference.source`、`report`、`complete` 和 `error` 事件中维护一个按时间顺序排列的事件投影。在流完成或出错时，它会重新加载持久化的证据链，这将成为权威的详细视图。乐观的计划/工具/证据记录被有意地排除了。

### 分割运行、历史记录和证据视图
在较大的屏幕上，固定宽度的任务历史记录支持重复调查，而主列包含事件条目、流式时间线、报告和一个证据部分。在较小的屏幕上，它们按相同顺序流动，不需要水平滚动依赖。密集的状态处理方式比营销风格的卡片更受青睐，因为操作员在事件期间需要进行比较和扫描。

### 显式可选警报 JSON
警报上下文字段仅接受对象。视图在任务创建前对其进行解析，并在无效时报告本地验证消息，同时保留规范化的后端错误路径以供服务器错误使用。自由格式的 JSON 字符串不会原样持久化；类型化的请求包含一个对象。

## Risks / Trade-offs

- [MCP/LLM 执行可能失败] → 显示服务器 SSE 错误和已保存的失败报告/证据，而不是声称得出结论。
- [重新加载会中断当前的 SSE 连接] → 已保存的任务仍保留在历史记录中，当后端完成时其证据链将可用；客户端不会声称本地断开的流已完成。
- [证据有效载荷可能很大] → 在时间线上显示有限的摘要，并在证据列表中使用可展开的有效载荷详细信息。
- [警报 JSON 难以编写] → 保持其为可选，并在请求前验证语法/对象结构。

## 迁移计划

1. 添加类型化客户端、存储、路由、组件和测试。
2. 在配置的 MCP 路径上运行真实的本地诊断，并确认流式状态以及已持久化的报告/evidence 渲染。
3. 回滚仅会还原前端路由和状态更改；已保存在后端的诊断任务保持不变。
