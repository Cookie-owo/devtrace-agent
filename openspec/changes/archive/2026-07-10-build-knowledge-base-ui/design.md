## 上下文

后端已公开 tenant 范围的知识库、文档上传/详情/删除以及文档索引任务 API。Vue 应用程序外壳具有受保护的 `/knowledge` 路由，但目前仅渲染占位符内容。一个遗留的 `protectedDataState` 将不相关的聊天和知识问题结合在一起，并且不再被应用程序外壳或聊天工作区所采用。

## Goals / Non-Goals

**目标：**
- 为已登录的 user 提供一个响应式的、基于服务器的知识工作区。
- 使用共享文档/indexing TypeScript 合同和已建立的类型化 API 传输。
- 使上传策略、重复行为、索引状态、失败原因、重试和破坏性操作可读。
- 仅轮询活动的非终止索引任务，使用有界间隔，并在视图卸载时取消轮询。

**非目标：**
- 创建或管理知识库，编辑文档内容，或添加浏览器端的文档存储。
- 更改文档、向量或索引后端契约。
- 在应用程序启动时自动开始文档索引。

## 决策

### 专用类型客户端和 Pinia 存储
在 `createApiClient` 和专注的 `useKnowledgeStore` 上创建 `knowledgeClient`，以镜像聊天架构。这可以防止新工作扩展过时的混合 `protectedDataState`，通过共享传输保持文件上传标题正确，并使单元测试请求和轮询转换直接。考虑在旧状态上添加适配器，但这样会保留聊天耦合并复制传输/错误行为。

### 显式 user 操作的索引生命周期
上传会创建文档，然后请求现有的 API 创建其索引任务。工作区会立即显示返回的任务，并在状态为非终止状态时每两秒轮询其特定端点。重建是一个有意的行操作。考虑过全局连续刷新，但被拒绝，因为它会产生不必要的已认证流量并掩盖哪个操作处于活动状态。

### 桌面表格，紧凑的移动文档列表
主工作区在较宽的屏幕上使用可访问的表格以方便扫描元数据，并在较窄的屏幕上将每行折叠成清晰的文档面板。文件选择保持原生，并包裹在一个拖放目标中；在请求之前，客户端会拒绝不可上传的文件，而后端仍具有权威性。

使用确认代替隐式的重复替换
初始上传始终使用 `overwrite=false` 发送。重复响应会记录待处理的文件和文档身份，然后提供一个显式的替换命令，该命令会使用 `overwrite=true` 重新发送。这遵守了 API 策略，并在服务器端破坏性向量清理发生前使替换操作可见。

## Risks / Trade-offs

- [在轮询期间可以离开页面] → 在存储中跟踪计时器 ID 并暴露 `stopPolling`，在路由卸载和身份验证登出时调用。
- [一个真实的索引任务可能比客户端轮询窗口更长] → 保留文档的最后报告状态，限制突发轮询，并保留手动刷新/重建控制。
- [浏览器验证可能与服务器策略不同步] → 从共享契约中导入策略；作为指导显示，并以原始后端错误呈现不变。
- [上传的文件内容无法预览] → 仅显示持久化的元数据和状态；内容预览仍在此范围之外。

## 迁移计划

1. 添加类型客户端、状态、工作区组件、路由和测试。
2. 使用实际上传和索引任务，与本地后端和运行中的 Milvus 服务确认行为。
3. 新路由替换占位符而不进行数据迁移。回滚包括恢复前端更改；服务器数据保持不变。
