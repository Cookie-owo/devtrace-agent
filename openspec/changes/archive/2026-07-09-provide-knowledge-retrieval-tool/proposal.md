## Why

知识库搜索必须作为显式的代理工具提供给模型，而不是固定的请求预步骤。这使得模型可以决定何时进行检索，同时保持tenant隔离、透明的引用和安全的空结果行为。

## 什么更改

- 添加一个后端知识检索工具，该工具接受查询文本、可选的 `topK` 和可选的过滤器，对查询进行嵌入，搜索 Milvus，并返回结构化的 chunk 匹配结果。
- 确保检索始终限定在已认证的 user 的 tenant 范围内，并且仅搜索 user 可访问的知识库。
- 添加用于检索工具输入、输出、匹配元数据、引用/来源参考和空结果的共享契约。
- 使 chat/RAG 在检索到 chunk 时能够发出引用来源。
- 保留现有的规则，即 user 问题不会将知识检索作为强制性的前置步骤。

## 能力

### 新功能
- `knowledge-retrieval-tool`: 定义了面向代理的文档检索工具，其输入/输出语义、权限过滤、引用来源行为和空结果合同。

### 修改的功能
- `api-and-sse-contracts`: 添加共享检索工具 DTO 并确保流式引用可以表示知识检索结果。
- `milvus-vector-store`: 明确检索工具所需的向量搜索范围，包括tenant作用域内的 topK 搜索和安全空结果。
- `authorization-and-tenant-isolation`: 要求检索工具调用使用经过身份验证的租户范围，并拒绝或限制未经授权的知识库过滤器。

## 影响

- 后端：检索工具服务/模块、向量存储协议使用、嵌入提供者使用、聊天/工具集成边界，以及测试。
- 共享合同：`packages/api-contracts` 检索 DTO 导出和 OpenAPI/SSE 模式更新。
- 前端：无需强制检索预取；共享的合约测试可能会使用检索/引用类型。
- 规范/文档：新增功能规范以及针对 API/SSE、Milvus 和授权行为的差异规范。
