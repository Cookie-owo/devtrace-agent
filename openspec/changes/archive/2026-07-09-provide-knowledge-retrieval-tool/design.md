## 上下文

该项目已经在 SQLite 中拥有由 tenant 拥有的文档元数据，将 chunk 向量写入 Milvus 的文档索引作业，一个共享的 `EmbeddingModel` 抽象层，以及与 tenant 和知识库过滤器结合使用的 `MilvusVectorStore.search_chunks()`。聊天和 AIOps API 表面已进行身份验证，但知识检索尚未作为代理工具公开。新工具必须复用这些边界，而不是添加单独的检索管道或在每次 user 消息之前强制进行检索。

## Goals / Non-Goals

**目标：**
- 提供一个具有稳定输入和输出契约的后端知识检索工具。
- 让模型仅在有用时调用检索，而不是将检索作为固定的聊天预处理步骤。
- 将每次检索调用限定于已认证的 user tenant 和允许的知识库。
- 返回包含 chunk 内容、源文档数据、元数据和相关性分数的结构化结果。
- 当 RAG 的回答使用了检索到的 chunk 时，返回参考源负载。
- 当没有 chunk 匹配时，返回显式的空结果。

**非目标：**
- 不新增向量数据库或嵌入式提供者。
- 不支持自动文档上传或启动时的自动索引。
- 除了当前的 user-id tenant 范围外，不支持多 tenant 组织模型。
- 不支持特定模型的 DashScope 或供应商私有检索 API。

## 决策

1. 在后端域名代码下添加一个聚焦的 `KnowledgeRetrievalTool` 服务。
   - 该工具接受一个带有 `query` 的类型化输入对象，可选的 `top_k` 和可选的过滤器。
   - 它依赖于现有的嵌入模型和向量搜索边界，将 Milvus 的细节保留在业务和代理代码之外。
   - 考虑的替代方案：直接向代理代码公开 `MilvusVectorStore.search_chunks()`。被拒绝，因为这会导致向量/过滤器细节泄露，并使权限检查容易被绕过。

2. 在向量搜索之前解决授权问题。
   - 当前 user 的 id 保持在 tenant 范围内。
   - 如果没有提供知识库过滤器，该工具将搜索当前 user 可访问的所有知识库。
   - 如果过滤器指定了超出可访问集合的知识库 ID，该工具会抛出统一的授权错误，而不是静默地扩大访问权限。
   - 考虑的替代方案：忽略未经授权的筛选并搜索交集。被拒绝，因为显式的禁止错误更容易审计，并且与受保护的 API 行为一致。

3. 在聊天流程中保持检索可选。
   - 检索工具被注册为可调用的工具边界，可以由未来的模型编排调用。
   - 聊天请求路径在模型调用前不能无条件地调用检索。
   - 考虑的替代方案：为每条聊天消息进行预取检索。被拒绝，因为 user 明确希望自主使用工具，而且预取会浪费 /vector 的嵌入RAG，这些查询并不需要。

4. 通过 `packages/api-contracts` 共享合同
   - 添加检索输入、过滤器、命中、输出和引用 DTO。
   - SSE `reference.source` 事件已存在；扩展其源有效负载预期，以包含足够的 chunk 字段，以便将检索结果映射到引用。
   - 考虑的替代方案：目前仅将工具契约保持为 Python 专用。被拒绝，因为前后端以后不得发明单独的事件或引用结构。

## Risks / Trade-offs

- 未经授权的过滤器处理可能会拒绝本可以返回允许子集的调用 -> 缓解措施：调用者可以省略过滤器以搜索所有可访问的知识库。
- TopK 默认值和限制可能需要根据语料库大小进行调整 -> 缓解措施：现在强制执行一个保守的最大值，并在工具边界保持可配置性。
- 引用生成依赖于使用返回的命中进行模型编排 -> 缓解措施：从工具返回确定性的引用 DTO，并在完全的聊天流编排存在之前就对其进行测试。
- Milvus 分数方向因指标而异 -> 缓解措施：保留原始向量分数作为 `score`，并在合同中避免声称归一化相关性。

## 迁移计划

1. 添加共享检索合约和测试。
2. 添加后端检索服务和带有假嵌入/vector存储的测试。
3. 添加API/chat边界测试，证明检索不是固定的预处理步骤。
4. 同步规范，验证并归档更改。
