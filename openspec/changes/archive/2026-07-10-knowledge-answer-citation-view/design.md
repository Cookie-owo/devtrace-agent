## 上下文

检索工具会生成完整的向量搜索命中结果，包括chunk内容、元数据、分数、文档ID和知识库ID。在这些命中结果到达流式聊天服务之前，会将其缩减为引用事件，然后该服务会将事件引用与助手消息一起持久化。Vue的对话记录仅显示标题芯片和精简的来源列表，因此操作员无法获得有用证据。

## Goals / Non-Goals

**目标：**
- 为检索输出、SSE 事件和持久化消息引用使用一个增强的共享参考形状。
- 在聊天中仅显示后端生成的证据字段和安全绑定的文本。
- 从检索元数据/源中确定性地对普通文档、SOPs 和诊断案例进行分类。
- 通过现有的 ownership-protected APIs 将基于文档的引用路由到经过身份验证的知识文档详情。

**非目标：**
- 更改向量搜索排名，揭示跨-tenant 源，添加浏览器端文档内容缓存，或在模型未使用检索时发明引用。

## 决策

### 扩展参考源合同
向共享参考源中添加可选的 `excerpt` 和 `knowledgeType` 字段。`excerpt` 由所选向量 chunk 得出，并在进入 SSE 框架或持久化元数据之前由后端进行限制。`knowledgeType` 是 `document`、`sop` 或 `diagnostic-case`；非知识引用仍保持兼容性并省略该字段。

### 在索引/retrieval边界进行分类
文档索引将稳定的文档源/类型元数据复制到每个向量 chunk 中。检索从该元数据和源值中推导出引用分类，保持类型分配由服务器所有并在聊天和 AIOps 消费者之间一致。现有文档如果没有明确的分类，则回退到 `document`。

### 转录本中的详细披露
在相关助手回答旁边和会话源列表中显示引用控制。选择一个会打开转录本中的非框架详细区域，显示其源标题、类型、限定摘录、分数、元数据，并在有文档 ID 时提供直接的知识导航操作。该存储不保留单独的真相来源：它投影 API 已经提供的持久化或流式引用。

### 用于直接文档详情的路由查询
在知识视图加载完当前 user 的文档后，会读取一个可选的 `documentId` 查询。它通过现有的客户端/存储边界打开匹配的文档，并忽略无法访问或缺失的 id，从而保持后端现有的 tenant 检查的权威性。

## Risks / Trade-offs

- [分块摘录过长或包含敏感文本] -> 在服务器端限制摘录并作为纯文本渲染；不暴露新的原始文档端点。
- [旧引用缺少增强字段] -> 渲染仅带标题的备用状态，同时保留其现有的源标签和链接。
- [在聊天持久化后引用的文档被删除] -> 保留证据详情，但当文档不可用时隐藏导航操作。
- [元数据可能很烦人] -> 渲染一个紧凑的键/值列表，使用字符串化值且不进行客户端推断。

## 迁移计划

1. 添加合同字段并通过流/persistence传播检索引用数据，同时进行测试。
2. 添加聊天证据控制和知识查询导航，涵盖流式传输和历史引用。
3. 验证真实的本地聊天流和文档导航，然后归档；回滚后较早的仅标题引用仍可读。
