## Why

长会话目前会把完整历史持续送入模型，用户既看不到上下文占用，也无法控制何时压缩，最终容易在模型上下文耗尽时无反馈地失败。需要把上下文预算和记忆压缩升级为会话级能力，让不同会话可以选择适合自己的策略并在达到硬上限前得到明确保护。

## What Changes

- 为每个聊天会话持久化独立的记忆模式、压缩摘要、已压缩消息边界和最后压缩时间。
- 支持“每 30 轮自动压缩”（默认）、“上下文占用达到 70% 自动压缩”和“手动压缩”三种模式。
- 手动模式在用户应用时由后端立即执行一次压缩，并允许后续再次显式压缩。
- 保留 SQLite 中的完整聊天历史；模型上下文使用压缩摘要和边界后的消息，不删除历史消息。
- 在会话 API 中返回当前上下文 token 估算、窗口大小和占用百分比，并提供记忆模式更新与压缩端点。
- 当前上下文占用达到 95% 时，前端禁用输入和发送并提示先手动压缩，后端同时拒绝新增消息。
- 在聊天输入框右侧展示会话当前上下文占比、记忆模式和应用/压缩操作。

## Capabilities

### New Capabilities
- `chat-memory-management`: 定义会话级上下文计量、三种压缩策略、摘要持久化和 95% 发送保护。

### Modified Capabilities
- `chat-sessions`: 会话生命周期响应增加独立记忆状态，清空会话同时重置压缩状态。
- `api-and-sse-contracts`: 增加记忆模式 DTO、模式更新/手动压缩端点及上下文上限错误码。
- `chat-experience`: 输入区展示上下文占比和记忆模式控件，并在达到硬上限时阻止发送。

## Impact

影响 SQLite 会话表和 Alembic 迁移、Repository 接口、聊天流式服务、共享 TypeScript/OpenAPI 契约、统一错误目录、Vue chat store/client/composer 以及相关后端与前端测试。LLM 配置增加按 `chatModel` 精确匹配的 `modelCapabilities`，不新增运行时环境变量或厂商私有 SDK。
