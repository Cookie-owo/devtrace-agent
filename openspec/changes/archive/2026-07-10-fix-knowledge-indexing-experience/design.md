## 上下文

知识文档流程现在涵盖了前端上传状态、后端索引任务、Qwen 嵌入和 Milvus。手动 API 冒烟测试显示了三个独立的运行时差距：前端上传在用户手动点击重新索引之前仍然可见地 `pending`，Qwen `text-embedding-v4` 拒绝了由 LangChain 的默认长度安全嵌入路径生成的标记化嵌入输入，并且当集合在第一个索引任务之前未初始化时，Milvus 向量写入失败。

## Goals / Non-Goals

**目标：**

- 使前端文档上传在开始时自动进行索引，并在任务完成后刷新可见状态。
- 保留手动索引/reindexing以供现有待处理或失败的文档使用。
- 使用显式维度和原始字符串输入行为配置 Qwen 嵌入。
- 确保在作用域删除和插入操作之前，文档索引初始化 Milvus 集合/indexes。
- 保持 Docker Compose Milvus 启动与可运行本地堆栈的镜像标签对齐。

**非目标：**

- 应用程序启动期间不自动上传文档。
- 索引完成时不会阻塞上传 API 响应。
- 不需要对服务器端作业队列或持久工作线程进行重新设计。
- 不替换 LangChain `ChatOpenAI` 以用于聊天模型访问。

## 决策

### 前端在上传后开始索引

在 `uploadKnowledgeDocument` 成功后，前端状态立即为返回的文档创建文档索引任务，将可见文档标记为 `indexing`，短暂轮询任务，然后刷新文档列表。这保持了后端上传端点 user-initiated 的快速性，同时消除了新文档似乎卡在 `pending` 的混淆前端状态。

考虑的替代方案：让后端上传端点创建一个索引任务。这会将元数据创建与索引调度耦合，并比此次体验修复所需更广泛地更改 API 合同。

### Qwen 嵌入保留原始字符串

默认的嵌入提供程序继续使用 OpenAI-compatible 路径，但会传递配置的 `embeddingDimensions=1024` 并禁用 LangChain 的令牌长度安全路径，因此请求会将原始字符串数组发送到 Qwen。阿里云的 OpenAI-compatible 嵌入 API 接受字符串或字符串数组；拒绝令牌 ID 数组。

考虑的替代方案：用直接的 OpenAI SDK 调用替换 LangChain `OpenAIEmbeddings`。禁用分词是最小的兼容性修复，并保持提供者实现接近现有的抽象。

### 索引在写入前初始化 Milvus

文档索引在删除之前的chunk或插入新的之前调用向量存储`initialize()`边界。这保持了导入时间和启动行为的惰性，同时使首次使用索引在空的Milvus实例上可靠。

考虑的替代方案：在FastAPI启动时初始化Milvus。这会减慢启动速度，并且即使开发者仅测试非知识功能时也会连接到外部基础设施。

### Compose 使用本地可运行的 Milvus 标签

Compose 堆栈使用一个 Milvus 独立镜像标签，可以在本地 Docker 环境中拉取并启动。其余的 Milvus 拓扑结构保持不变。

## Risks / Trade-offs

- [风险] 前端轮询可能在长时间运行的索引任务完成前停止。 -> 缓解措施：它仍然会存储任务并刷新文档列表；手动 `Index/Reindex` 仍可用。
- [风险] 禁用嵌入标记拆分意味着非常大的 chunk 依赖于配置的 chunker 在供应商限制范围内。 -> 缓解措施：文档 chunking 已经在嵌入之前限制 chunk 内容长度。
- [风险] 第一个索引任务会支付集合初始化成本。 -> 缓解措施：初始化仅在实际使用索引时发生，并且位于向量存储边界之后。
- [风险] Milvus 图像标签可能在上游发生变化。 -> 缓解措施：Compose 验证和本地启动烟雾测试会在早期捕获拉取/启动失败。

2. 更新前端上传状态、后端嵌入提供者配置和文档索引服务。

4. 验证后端、前端、OpenSpec 和本地知识上传/索引的烟雾测试行为。
