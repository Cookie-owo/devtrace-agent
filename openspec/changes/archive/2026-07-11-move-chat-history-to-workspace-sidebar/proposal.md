## Why

聊天历史目前占用聊天工作区内部的一整列，与全局左侧导航重复形成两层侧栏，压缩了对话阅读宽度。与此同时，保存 Skill 配置会替换配置对象并意外重新展开用户已经收起的系统提示词，破坏了局部交互状态。

## What Changes

- 将历史对话列表迁移到全局左侧栏，并仅在对话工作区显示。
- 在左侧栏的对话入口提供新建对话按钮，通过同一侧栏完成创建、切换和删除会话。
- 移除聊天工作区内部的历史会话列，让主区域用于对话和对话配置。
- 移除 user 消息的灰色气泡和额外内边距，使其与 assistant 消息使用同一正文展示样式，同时保留 user 靠右、assistant 靠左的对话分流。
- 完全移除聊天工作区控件和输入容器的绿色或灰色焦点矩形框。
- 修复配置对象刷新导致系统提示词自动重新展开的问题，保存 Skill 后保持用户当前的展开/收起状态。
- 记录前端仅面向桌面 Web，不为该能力增加移动端专用交互。
- 固定智能诊断桌面工作区高度，让长报告只在最终报告正文区域内滚动。
- 移除对话、知识库和智能诊断路由内容区的居中宽度限制与外层留白，让各业务视图铺满左侧栏右侧的桌面空间。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `vue-app-shell`: 全局工作区侧栏在对话路由中承载新建入口和历史会话导航，路由内容区采用无外层留白的 edge-to-edge 桌面应用画布。
- `chat-experience`: 聊天主区域不再包含历史会话列，user/assistant 使用同一消息样式但保留左右分流。
- `chat-prompt-skill-configuration`: Skill 配置保存不得改变系统提示词的局部展开状态。
- `aiops-diagnosis-ui`: 智能诊断工作区固定在桌面视口中，长报告使用内部滚动容器。

## Impact

影响 Vue 工作区布局、工作区导航、聊天视图、会话列表组件、系统提示词组件、AIOps 工作区、报告组件、仓库指南及其测试。后端 API、会话数据结构和配置契约不变，不新增依赖。
