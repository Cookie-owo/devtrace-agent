## 上下文

后端目前具有干净的 Python src 布局和一个 LLM 提供者边界，但没有持久化的应用内存。即将推出的聊天和 AIOps 工作流需要持久化对话状态、诊断执行状态、报告、工具调用审计数据以及 LangGraph checkpoint 信息，而不会将业务代码与 SQLite 表或 SQLAlchemy 内部结构耦合。

SQLite 是第一个实现目标，因为它使本地开发保持简单，并且适用于初始的单进程后端。该边界必须保持足够与数据库无关，以便以后引入 PostgreSQL。

## Goals / Non-Goals

**目标：**

- 为聊天会话、聊天消息、AIOps 诊断任务、诊断报告、工具调用审计条目和 AIOps LangGraph checkpoint 定义 SQLAlchemy ORM 模型。
- 通过 Alembic 管理内存模式，包括一个可以构建全新 SQLite 数据库的初始迁移。
- 为所有内存表面提供仓库协议和 SQLite 实现。
- 支持按会话、诊断任务和包含的时间范围进行历史查询。
- 保持面向应用程序的记录和查询对象与 ORM 模型类独立。

**非目标：**

- 构建聊天编排，AIOps 执行，LangGraph 图表，或流式 API。
- 在此次更改中添加对 PostgreSQL 的支持。
- 添加向量数据库存储、嵌入搜索、保留作业或静态加密。
- 运行实时 LLM 调用或供应商特定的 SDK 代码。

## 决策

### 决策：异步 SQLAlchemy 2.x ORM 使用 `aiosqlite`

使用 SQLAlchemy 2 个类型声明映射，包含 `Mapped` 和 `mapped_column`、异步引擎以及 `async_sessionmaker`。这与后端的异步测试设置相匹配，使仓库方法具有自然的异步签名，并避免阻塞后续的 API 处理程序。

考虑过的替代方案：
- 同步 SQLAlchemy 会话：对测试更简单，但一旦 HTTP 处理程序和模型工作流变为异步，就会变得笨拙。
- 原始 `sqlite3`：依赖项更少，但它会将 SQL 详情推入仓库，并使未来的 PostgreSQL 替换更困难。

### 决定：Alembic 拥有架构创建权

后端将包含 `alembic.ini`、`alembic/env.py` 以及一个初始的内存模式版本。测试可以针对临时 SQLite 文件运行迁移；应用程序代码在生产模式路径中不会调用 `Base.metadata.create_all()`。

考虑过的替代方案：
- 在启动代码中使用 `create_all()`：方便，但不会提供迁移历史或生产就绪的升级路径。
- 手动编写的 SQL 迁移脚本：与 SQLAlchemy 元数据集成度较低，且不利于后续 PostgreSQL 实现的可移植性。

### 决策：仓库协议与SQLite实现分离

业务代码将依赖于仓库协议和数据类记录，如 `ChatSessionRecord`、`ChatMessageRecord`、`DiagnosticTaskRecord` 和 `ToolCallAuditRecord`。SQLite 特定的实现位于基础设施模块中，并在数据类和 ORM 行之间进行转换。

考虑过的替代方案：
- 将 SQLAlchemy 模型作为领域对象公开：实现快速，但会将表结构和会话行为泄露到服务中。
- 一个用于所有内存操作的大型仓库：类更少，但边界较弱，后续替换更困难。

### 决策：JSON 用于灵活工作流数据的有效载荷列

消息元数据、诊断输入/结果、报告有效负载、工具参数/结果以及 checkpoint 有效负载将使用 SQLAlchemy JSON 列。这可以保留结构化数据，而不会将第一个模式过度拟合到不稳定的工作流有效负载。

考虑过的替代方案：
- 将每个有效负载格式标准化为多个表：更强的关联约束，但在 chat/AIOps 有效负载合约仍在演进时过于提前。
- 存储不透明的文本块：容易，但会失去结构化的往返行为和查询可读性。

## Risks / Trade-offs

- SQLite 的写入并发受到限制 -> 仓库保持事务小，并且接口允许以后替换为 PostgreSQL。
- JSON 的负载可能变得不一致 -> 数据类构造函数和测试定义了所需的记录结构，当服务契约稳定时可以添加更丰富的验证。
- 异步 Alembic 的设置比同步迁移更复杂 -> 保持 `env.py` 接近 Alembic 中记录的异步模式，并直接测试迁移。
- 一旦业务工作流程到来，仓库接口可能需要扩展 -> 为当前的存储和查询需求定义专注的方法，避免过早使用通用查询构建器。

## 迁移计划

1. 添加 SQLAlchemy、Alembic 和 `aiosqlite` 依赖项。
2. 添加数据库配置和异步会话工厂辅助函数。
3. 添加内存 ORM 模型和初始 Alembic 迁移。
4. 添加仓库记录、协议和 SQLite 实现。
5. 添加在临时数据库上运行迁移的测试，并验证仓库的写入和查询操作。
6. 记录本地数据库配置和迁移命令。

此初始模式的回滚很简单：删除内存存储库包并降级/删除为本地开发创建的 SQLite 数据库。不包括生产数据迁移。

## 开放问题

此更改没有待解决问题。PostgreSQL 连接详细信息、保留策略和 checkpoint 有效负载兼容性将在这些运行时服务存在后在后续更改中处理。
