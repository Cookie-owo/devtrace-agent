## 上下文

本地 CLS MCP 服务器在端口 3000 上配置为 SSE，但不存在后端 MCP 客户端。聊天 Agent 已经具有工具注入点和通用工具调用审计持久化。

## Goals / Non-Goals

**目标：** 使用 MCP SSE 协议进行发现和调用，为 LangChain 包装发现的工具，强制设置超时/重试，显示明确的失败情况，并报告 readiness。

**非目标:** 不提供模拟的 MCP 服务器，不生成伪造的回退数据，也不替换官方的 CLS MCP 实现。

## 决策

使用官方的 Python MCP 客户端，并使用由应用拥有的适配器。每次调用都会使用配置的本地 SSE 端点，发现 readiness 上的工具，验证工具名称，并通过 MCP 进行调用。网络故障会作为显式的工具错误返回，并由现有的聊天生命周期进行审计。凭据仍由本地 MCP 容器拥有。

## Risks / Trade-offs

- [MCP 服务器不可用] -> readiness 为healthy 并且聊天返回明确的MCP 无法使用错误。
- [工具调用延迟] -> 有限超时和有限重试，无模拟回退。
- [工具输出形状不同] -> 保留JSON-安全的MCP 输出，并让Agent 仅解释返回的数据。
