## Why

运维人员需要一种直接查看当前外部告警并将真实告警转化为有据可依的 AIOps 诊断的方法。当前的 AIOps 工作区仅接受手动输入的 JSON，这使得事件调查变慢，并容易导致告警上下文丢失。

## 变更内容

- 添加一个已配置且经过认证的后端边界，用于从真实的兼容 Alertmanager 的 Alerts API 读取活跃告警。
- 添加共享的 API 契约，用于规范化的活跃告警数据以及明确的提供方故障响应。
- 添加一个 AIOps 工作区面板，用于列出当前告警并使用所选告警的完整上下文启动 AIOps 诊断。
- 保持远程告警访问仅限实时模式：不包含运行时模拟配置、种子告警或伪造的回退结果。

## 能力

### 新功能
- `active-alert-subscription-entry`: 读取活动的外部警报，并根据所选警报创建当前用户的 AIOps 诊断。

### 已修改的功能
- 无。

## 影响

- 影响已跟踪的项目配置、后端 alert-provider/API 代码、共享 API 契约、AIOps 前端状态/组件以及自动化测试。
- 新增对已配置的兼容 Alertmanager 的 `/api/v2/alerts` 端点的实际依赖；不可用的提供程序将表现为标准化的服务错误。
