## 上下文

API 响应封装包含请求 ID，但请求完成日志和本地请求指标并不始终可用。外部日志和监控系统仍位于项目 Compose 堆栈之外。

## Goals / Non-Goals

**目标：** 提供安全的结构化请求日志、响应相关标头和进程内操作指标。

**非目标:** 部署外部可观测性系统，存储请求体，或记录凭据和承载令牌。

## 决策

- 使用一个 FastAPI 中间件来分配或遵守 `X-Request-ID`，在每次响应中返回它，测量延迟，记录结构化的完成字段，并增加一个线程安全的内存指标收集器。
- 从轻量级 `/metrics` 端点暴露 JSON 指标，用于本地开发和爬虫适配器。不要添加外部依赖项。
- 永远不要记录请求头/请求体的值；通用中间件中不可用路径模板，因此在排除查询字符串后仅记录请求路径。

## Risks / Trade-offs

- [进程重启时指标重置] → 作为本地基线指标记录，不用于持久化监控。
- [无限制的路径基数] → 仅使用现有应用程序路由的请求路径和聚合总数/状态类别。
