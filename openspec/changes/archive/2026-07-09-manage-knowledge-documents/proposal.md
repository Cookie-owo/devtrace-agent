## Why

知识库文档目前仅通过占位符摄入路径进行表示，因此user无法显式上传、检查、删除或了解其自身文件的索引状态。在检索和索引成为可靠产品行为之前，系统需要一个user范围的文档管理界面。

## 什么更改

- 添加经过身份验证的知识文档上传功能，明确限制文件大小、允许的文件类型、重复哈希处理和覆盖行为。
- 添加文档列表和详细API，这些内容暴露文件名、大小、MIME类型、内容哈希、上传时间、状态、索引状态以及owner元数据。
- 添加文档删除功能，该功能会删除文档记录，并同步请求删除该文档的Milvus chunk。
- 在仓库协议后添加基于SQLite的文档仓库，以便业务/API代码不依赖于表细节。
- 为列出 user 文档、选择要上传的文件、查看文档状态和删除文档添加前端文档管理控件。
- 移除在应用程序启动期间文档会被上传的任何预期；上传始终由 user 引发。

## 功能

### 新功能
- `knowledge-documents`: 用户作用域的知识库文档管理，包括上传策略、元数据、列表、详情、删除和索引状态。

### 修改后的功能
- `api-and-sse-contracts`: 添加文档请求/响应模式以及受保护的文档路由，并明确验证/冲突行为。
- `authorization-and-tenant-isolation`: 要求文档操作和与文档相关的向量作用域限定为当前用户。
- `memory-repositories`: 添加仓库边界和SQLite知识文档元数据和查询模式的持久化。
- `milvus-vector-store`: 添加文档范围的向量删除，以便在删除文档时清理块向量。

## 影响

- 后端 FastAPI 应用、响应处理、文档服务/存储库代码、SQLAlchemy 模型以及 Alembic 迁移。
- 共享的 TypeScript API 合同和 OpenAPI 文档。
- Vue 前端受保护数据客户端/state 和已认证的工作区 UI。
- Milvus 用于文档范围删除过滤器的向量存储抽象。
- 后端、前端和合约测试以及 OpenSpec 规范。
