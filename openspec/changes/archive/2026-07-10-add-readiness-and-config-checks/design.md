## 上下文

`/health` 检查 Milvus 和 `/health/mcp` 检查本地 MCP 服务器，而配置的 LLM 提供商公开了一个安全的 `check_readiness` 方法。这些检查是断开的，工作区标题当前报告的是静态连接状态。

## Goals / Non-Goals

**目标：** 在一个类型化的端点下聚合安全组件 readiness ，并实现常规工作区连接的实时运行。

**非目标:** 暴露 API 密钥或其他秘密，修改配置，为每个前端页面加载调用完整的提供者检查，或添加外部监控基础设施。

## 决策

- 保持 `/health` 轻量级，并用于前端标题。添加 `/readiness` 以对 Milvus、LLM 和 MCP 进行显式的完整探测。
- 在线程池中执行阻塞的 Milvus 探针，并并发运行独立的 LLM/MCP 检查。
- 返回一个标准化的、安全的组件状态有效负载；当任何必需的依赖项不可用时使用 `503`。
- 在全局 shell 中仅显示轻量级后端可访问性。完整的 readiness 检查仍需显式执行 API 操作，以避免不必要的模型调用。

## Risks / Trade-offs

- [LLM readiness 消耗提供者请求] → 为显式的 `/readiness` 调用者保留。
- [一个依赖不可用] → 返回其他所有组件的结果以及降级状态，以便恢复操作可执行。
