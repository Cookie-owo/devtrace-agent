## 上下文

请求接收 `X-Request-ID` 并发出 JSON 完成日志，但请求 ID 不会传递到下游服务。文档索引在后台任务中运行，代理异步执行，且 MCP 调用包含可能敏感的工具输入和输出。该项目必须能够在不使用外部日志收集器的情况下本地运行。

## Goals / Non-Goals

**目标：**
- 发出一个稳定的 JSON 事件格式，包含 `event`、请求 ID（如果可用）以及安全的操作字段。
- 通过上下文变量在异步任务中传播请求关联。
- 覆盖请求错误、索引、聊天/AIOps 代理生命周期以及 MCP 工具生命周期。
- 防止敏感信息和无限制的业务负载进入日志事件。

**非目标：**
- 添加分布式追踪基础设施、持久化日志存储、外部指标导出器，或日志 user 消息内容/工具结果数据。

## 决策

### 共享的包级可观测性边界
创建 `super_ai.observability` 而不是将 API 辅助函数导入服务中。它拥有请求 ID 上下文变量、JSON 事件发射、经过时间辅助函数，以及一个递归的允许列表/屏蔽策略。业务模块仅使用标识符和有限的操作元数据调用它。

### 关联跟随异步工作
API 中间件在请求处理前设置请求 ID，并在完成后重置它。Python 任务创建会复制上下文，因此标准的计划索引保留原始请求 ID，而无需将框架对象传递到业务服务中。独立作业会发出一个没有请求 ID 的事件，而不是发明一个连接。

### 数据最小化事件字段
请求事件包含方法/路径/状态/延迟；索引事件包含任务/文档ID和chunk计数；代理事件包含会话或任务ID和生命周期状态；MCP事件包含工具名称、参数键名、状态和持续时间。错误日志使用错误类型或目录代码，而不是原始异常消息。记录器递归地隐藏常见的凭据键名作为纵深防御层。

## Risks / Trade-offs

- [手动调用的作业可以没有上下文] -> 不带请求 ID 发出事件，并保留任务/会话标识符。
- [在一个边界缺少事件] -> 为每个所需类别添加聚焦的 caplog 测试。
- [清理器过于宽松] -> 不要将原始消息、请求、参数或输出传递到事件字段中；断言已知的秘密永远不会出现。
- [JSON 日志在本地可读性较差] -> 保持键紧凑，并在标准日志输出中每行一个事件。

## 迁移计划

1. 为关联的、脱敏的请求/错误/索引/代理/MCP 事件添加失败测试。
2. 引入共享的日志边界并为每个生命周期添加探针。
3. 运行本地工作流，检查发出的事件，然后同步、归档、提交和推送。
