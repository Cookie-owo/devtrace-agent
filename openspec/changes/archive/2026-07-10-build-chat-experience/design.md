## 上下文

后端已经拥有所有聊天持久化功能，并为会话生命周期、历史记录、流式发送、工具调用审计和引用元数据提供了类型化的 API。Vue shell 提供了一个经过身份验证的 `/chat` 路由和通用传输原语，但该路由目前只是一个空占位符。现有的临时受保护数据状态混合了文档和聊天相关的问题，不适合用于专注的、可独立测试的对话工作区。

## Goals / Non-Goals

**目标：**

- 提供一个可用的持久化聊天工作区，具有后端支持的会话历史记录，并且没有 localStorage 域缓存。
- 从共享合约中渲染令牌流、工具生命周期状态、源引用和最终持久化的消息。
- 安全地渲染助手 Markdown，包括代码块和链接，同时禁用不可信的原始 HTML。
- 提供平静、响应迅速的控件，用于启动、选择和删除对话。

**非目标：**

- 修改 Agent 提示、工具选择、检索策略或后端流语义。
- 构建详细的引用检查器；后续的引用视图更改将扩展源细节和导航。
- 添加本地仅有的对话缓存或离线发送队列。

## 决策

### 使用专用的聊天客户端和 Pinia 存储

`ChatClient` 将组合 shell 的通用 API 和 SSE 客户端，`ChatStore` 将负责会话、选定的历史记录、实时工具活动、引用和请求生命周期。它将流完成与后端会话响应进行协调，然后重新加载工具审核，因此浏览器状态仍然是服务器的视图，而不是系统中的记录。

考虑过的替代方案：

- 扩展现有的联合受保护数据状态：被拒绝，因为知识和聊天加载/error生命周期变得耦合，难以独立测试。  
- 在localStorage中持久化消息草稿或历史记录：被拒绝，因为服务器是必需的主要存储，过时的tenant数据不安全。

### 将流事件作为持久化 UI 状态呈现

该存储在迭代输入的 `SseEvent` 流之前会创建一个临时的 user 消息和助手草稿。`content.delta` 扩展了草稿；`tool.call` 更新了工具活动条目；`reference.source` 追加了源引用；`complete` 刷新了持久化的历史记录和审计日志。`error` 通过 shell 反馈存储成为可见的标准化错误，保留发送的 user 消息，如同后端所做的那样。

### 使用隔离的安全 Markdown 渲染器

一个小型 `MarkdownContent` 组件将使用 `marked`，并禁用原始 HTML，同时使用 DOMPurify 作为最终的清理器。该组件是唯一创建答案 HTML 的地方，从而在其他地方保留 Vue 的正常文本插值。这避免了临时渲染，并使渲染行为易于进行单元测试。

### 将聊天界面作为专注的工作区来构建

路由内容将使用固定宽度的对话列表、流动的传记/创作器列以及在宽屏上的上下文活动面板。窄屏上会将会话选择器堆叠在传记上方，并将发送命令保留在创作器中。工具/审计和源详细信息将使用语义披露区域，而不是嵌套的装饰性卡片。

## Risks / Trade-offs

- [长时间的输出可能会增长 DOM] → 仅渲染当前会话，并在重新加载持久化会话后清除临时流状态。
- [流失败可能会留下乐观草稿] → 将草稿标记为失败并显示合约错误，然后允许 user 重试新的发送而不声明持久化。
- [Markdown 可能包含不安全的 HTML] → 在解析器中禁用原始 HTML，并在 `v-html` 之前对最终输出进行清理。
- [工具输出可能很大或敏感] → 显示服务器提供的审计摘要，而不是原始的无限制输入/输出负载。

## 迁移计划

1. 添加安全的 Markdown 依赖项和失败的单元测试/component。
2. 添加类型客户端、聊天存储和注销重置边界。
3. 用会话列表、对话记录、创作者、源和工具活动组件替换聊天占位符。
4. 验证 API/SSE 与本地后端和真实流媒体消息的集成。
5. 回滚是前端的还原操作；所有现有的服务器端聊天数据保持不变。
