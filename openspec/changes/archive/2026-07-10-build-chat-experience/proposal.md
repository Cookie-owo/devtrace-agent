## Why

已认证的聊天路由目前仅包含占位符，尽管后端已保存会话并公开类型化的流式 RAG 事件。用户需要一个完整的、可读的对话工作区，能够理解流式答案、工具活动和源使用情况，而无需依赖本地浏览器历史记录。

## 什么更改

- 将 Chat 路由占位符替换为基于持久化聊天会话 API 的响应式对话工作区。
- 添加类型化的聊天客户端和 Pinia 状态，用于会话创建、选择、删除、历史加载和流式发送。
- 在流式输出期间和之后安全地渲染助手的 Markdown。
- 表面知识参考和工具调用进度/result 摘要以及相关对话。
- 添加清晰的空、加载中、发送中和错误状态，而不将 localStorage 视为会话数据存储。

## 功能

### 新功能
- `chat-experience`：一个持久化、流式传输、具有源感知功能的聊天用户界面，仅由共享的 API 和 SSE 合同构建而成。

### 修改的功能

无。

## 影响

- 替换 `/chat` 前端占位符，并在 `apps/frontend` 下添加特定于聊天的客户端、存储、组件、样式和测试。
- 从 `packages/api-contracts` 中复用现有的会话、聊天消息、工具审计和 SSE 类型。
- 向前端工作区添加安全的 Markdown 渲染依赖项。
