## 上下文

SQLite 已经存储了诊断任务、报告、工具调用审计和 LangGraph checkpoint 负载。API 当前接受诊断任务，但不会执行它。后端已经具备 tenant 范围的检索工具、一个真实的本地 CLS MCP 客户端、共享的 SSE 编码，以及配置的 Qwen 提供商。

## Goals / Non-Goals

**目标：**

- 运行每个已接受的诊断通过显式的 LangGraph `Planner -> Executor -> Replanner -> Report` 状态图。
- 在 Planner 形成计划之前检索 SOP 证据，仅调用实际注册的工具，并使缺乏 SOP 证据可见。
- 在现有的 owner 范围仓库边界内，持久化任务状态、证据、工具审计、节点 checkpoints 和最终报告。
- 使用现有的 SSE 事件类型流式传输稳定、经过身份验证的诊断生命周期。

**非目标：**

- 构建通用的工作流编辑器、后台作业队列或前端 AIOps 仪表板。
- 创建模拟 MCP 响应，发明观察结果，或诊断工具返回证据之外的外部系统。
- 替换现有的聊天 Agent 实现。

## 决策

### LangGraph 控制流程；服务拥有集成

诊断服务创建一个带有四个命名节点的微型类型化 LangGraph 状态图，并从 Replanner 进行条件路由。节点函数将检索、LLM 规划、MCP 执行、持久化和 SSE 收集委托给注入的服务。这使得图行为可观察且可进行单元测试，而无需在节点中嵌入 SQL 或传输逻辑。考虑过一个自由形式的 Agent 循环，但它无法保证所需的 SOP 优先阶段或命名的计划/重新计划阶段。

### SOP 检索是确定性的，并在 LLM 规划之前发生

Planner 节点在要求 Qwen 生成结构化计划之前，会直接调用现有的 tenant 范围内的 `KnowledgeRetrievalTool`。其结果被存储为证据并作为参考事件发出。计划提示包括检索到的 SOP 和一个显式的 `noSopMatched` 标志。如果没有结果存在，服务会发出任务状态事件，并指示模型生成一个明确标记的通用计划。允许 LLM 决定是否检索被拒绝，因为需求规定必须首先进行 SOP 查找。

### 计划仅限于注册的工具调用

计划器和重新计划器返回具有有限步骤的验证过的 JSON。Executor 识别本地知识检索工具以及由 `MultiServerMCPClient` 提供的发现的真实 MCP 工具；未知工具或格式错误的参数会生成失败的工具审计和证据项，而不是伪造的结果。初始操作路径优先使用 CLS `SearchLog`，而发现的 MCP 工具仍可用于显式计划。

### 持久化是增量的且作用于 owner 范围

服务在图执行前创建一个 `running` 诊断任务，在每个节点后记录一个 checkpoint，通过 `ToolCallAuditRepository` 写入工具生命周期审计，并存储最终报告以及 `succeeded` 或 `failed` 任务状态。现有的诊断仓库方法扩展了一个 owner 范围的任务更新操作。考虑过一个 LangGraph 特定的数据库 checkpointer，但显式的节点快照可以干净地适应现有的仓库契约并保留所需的任务/线程命名空间。

### SSE 在图执行期间被收集

节点将共享事件负载附加到状态；API 在每个节点转换后按顺序流式传输它们，然后发出 `report` 和 `complete` 或 `error`。这保留了现有 API 的单请求 SSE 结构，并确保流式处理的声明与持久化任务数据相对应。该任务在请求的异步流中运行，因此如果客户端观察到终端输出，则不会留下未跟踪的后台工作。

## Risks / Trade-offs

- [模型返回格式错误的规划 JSON] -> 采取防御性解析，回退到一个有界的一般性证据收集步骤，并在事件/报告中记录回退情况。
- [MCP 服务器或 CLS 不可用] -> 将相关的工具调用和诊断任务标记为失败，并使用安全的显式错误；绝不替代模拟输出。
- [没有索引 SOP] -> 发出明确的无 SOP 状态和报告部分；仅使用通用计划语言和真实执行证据。
- [长时间的 MCP 调用保持 SSE 请求打开] -> 重用配置的超时和重试限制，并限制总计划步骤数。
- [LLM 报告夸大证据] -> 仅将已保存的证据输入报告提示，并在执行未产生任何证据时要求得出“无证据”的结论。

## 迁移计划

1. 添加显式的 LangGraph 依赖和 AIOps 服务，然后扩展诊断仓库协议和 SQLite 实现以处理状态转换。
2. 添加 API-contract 和后端端点支持，用于诊断流和持久化报告负载。
3. 运行 Alembic 迁移（如果现有的任务/报告/checkpoint 表仍然足够，则不需要模式迁移），启动本地 MCP/后端/前端进程，并执行一个基于 CLS 的诊断。
4. 通过回滚应用程序提交进行回退；通过现有的仓库查询仍可读取持久化的诊断行。

## 开放性问题

- 初始CLS聚焦的诊断流程中无。可以通过在执行器中注册其真实的MCP工具来添加其他操作系统。
