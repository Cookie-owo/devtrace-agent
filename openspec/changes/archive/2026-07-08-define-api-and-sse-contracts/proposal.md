## Why

聊天、知识库、索引和 AIOps 的功能工作在前端和后端实现开始之前，需要一个共享的 API 和流式词汇表。现在定义这些合约可以防止每一方单独发明 HTTP 响应包装器、错误有效载荷或 SSE 事件结构。

## 什么更改

- 将`packages/api-contracts`扩展到HTTP响应、错误代码、OpenAPI路径和SSE事件的共享源中。
- 为成功、业务错误、验证错误和系统错误定义统一的HTTP响应封装。
- 定义适用于API响应和SSE错误的稳定错误代码和结构化错误消息。
- 添加一个OpenAPI契约，涵盖health检查、聊天、知识库、索引任务和AIOps诊断。
- 为聊天流和AIOps诊断进度定义SSE事件，包括内容差异、工具调用、引用、任务状态、报告、完成和错误。
- 添加测试以证明前端代码使用相同的契约导出，而不是临时事件结构。

## 能力

### 新功能
- `api-and-sse-contracts`: 定义共享后端 API、HTTP 响应、错误、OpenAPI 和 SSE 事件契约。

### 修改的功能
- `project-foundation`: 强化共享 API 合同包的要求，使得前端和后端实现必须使用相同的合同源代码。

## 影响

- 影响`packages/api-contracts`源代码、包元数据和测试。
- 仅影响前端测试，以证明合约的使用。
- 为合约覆盖和单源使用添加OpenSpec需求。
- 不添加运行时后端端点或前端产品界面。
