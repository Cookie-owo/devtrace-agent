## 上下文

当前基础架构包含一个最小的 `packages/api-contracts` 包，其中仅包含一个 health 合同。下一步的实现波次将为聊天、知识库、索引和 AIOps 添加后端端点和前端消费者。如果没有共享的合同层，前端和后端可能会在响应封装、错误处理和流式事件负载上出现偏差。

此更改仅定义合约工件。它不会实现运行时后端端点、持久化模型、LLM 调用、向量索引或用户界面工作流。

## Goals / Non-Goals

**目标：**
- 导出可重用的 TypeScript 合同，用于 HTTP 成功和错误响应。
- 导出一个稳定的错误代码目录，包含类别、HTTP 状态和默认消息。
- 导出一个带类型的 OpenAPI 文档，涵盖 health、聊天、知识库、索引任务和 AIOps 诊断端点。
- 导出区分的 SSE 事件类型，用于聊天和 AIOps 流。
- 添加测试以证明合同结构以及前端代码可以使用它们。

**非目标：**
- 不实现 FastAPI 路由。
- 未生成客户端/server代码。
- 无身份验证、授权、持久化、Milvus、腾讯 CLS、MCP 或 LLM 提供商行为。
- 除了证明契约消费的测试外，无前端产品屏幕。

## 决策

### 决定：目前将合同作为手写的 TypeScript 保留
该包将直接从聚焦的源文件中公开 TypeScript 类型和常量。这在没有后端模式生成器的情况下，保持了第一层契约的简单和可读性。

考虑的替代方案：
- 从后端模型生成合约：被拒绝，因为后端路由模型尚未存在。
- 使用 JSON Schema 作为唯一来源：被拒绝，因为当前消费者是 TypeScript 优先，需要易于使用的区分联合类型。

### 决策：将 OpenAPI 作为类型化常量模型化
OpenAPI 文档将被导出为 `OPENAPI_CONTRACT`，其中保留模式和路径在 TypeScript 中，以便测试可以检查覆盖率，消费者可以导入一个工件。

考虑过的替代方案：
- 仅存储 YAML：被拒绝，因为测试和前端导入需要另一个解析器。
- 仅存储 TypeScript 端点常量：被拒绝，因为未来的后端工具链从真正的 OpenAPI 结构文档中受益。

### 决策：对 HTTP 响应和 SSE 事件使用区分联合类型
HTTP 信封使用 `ok: true | false`。SSE 事件使用 `type` 分类器和共享的元数据。错误事件重用共享的 API 错误消息结构。

考虑过的替代方案：
- 自由格式的 SSE JSON 有效负载：被拒绝，因为它们可能导致前端/后端代码不同步。
- 为HTTP和SSE单独定义错误结构：被拒绝，因为它重复了翻译逻辑并削弱了一致性。

### 决策：保持端点覆盖范围广泛，但减少有效负载细节
OpenAPI 合同将涵盖所需领域并使用稳定的请求/响应模式，但将避免对属于后续实现提案的产品内部进行过度规范。

考虑过的替代方案：
- 完全详细的领域模式现在：被拒绝，因为聊天、知识库、索引和 AIOps 内部结构尚未实现。
- 仅 health 和聊天现在：因 user 明确要求覆盖所有列出的领域而被拒绝。

## Risks / Trade-offs

- 合同常量可能在以后与运行时后端模型不同 → 缓解措施：未来的后端提案必须从 `packages/api-contracts` 导入或生成，并且测试应将运行时模式与这些导出进行比较。
- 手动编写的 OpenAPI 可能会变得冗长 → 缓解措施：保持模式小而简洁，并按职责拆分文件。
- 以 TypeScript 优先的合同无法直接从 Python 导入 → 缓解措施：后端对齐是一项要求；当后端 API 实现时，后续提案可以添加生成/导出步骤以供 Python 模型使用。
- SSE 事件目录可能需要以后添加新的事件类型 → 缓解措施：使用显式的字面量事件类型，并通过 OpenSpec 的更改来添加新事件。

## 迁移计划

1. 为 OpenSpec 和 SSE 合同添加 OpenSpec 要求。
2. 为 HTTP 封套、错误代码、OpenAPI 覆盖范围、SSE 事件类型覆盖范围以及前端使用添加失败测试。
3. 在 `packages/api-contracts/src` 下实现聚焦的合同模块。
4. 更新前端测试代码以使用共享的合约导出。
5. 运行 OpenSpec、打包、后端和前端验证。
6. 同步规范并归档已完成的更改。

## 开放问题

此合同定义更改无相关内容。后续的 API 实现提案应决定生成的 Python 模型策略和具体的端点行为。
