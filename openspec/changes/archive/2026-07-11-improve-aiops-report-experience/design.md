## Context

Report 节点当前通过确定性 `_report_content` 函数拼接英文摘要，未调用 LLM。报告已存入 SQLite 并通过 SSE 返回，但前端中栏时间线仅把它作为单个事件内嵌，右栏证据链反而渲染完整正文，导致正式产物不在视觉主轴。通用 `MarkdownContent` 对所有标题使用相同字号且没有表格样式，无法支撑长篇运维报告。

## Goals / Non-Goals

**Goals:**

- 使用现有 LLM Provider 生成结构稳定、纯 Markdown、面向中文运维人员的最终报告。
- Prompt 只提供诊断输入、告警、计划、SOP 和真实执行证据，并明确禁止补全未知事实。
- LLM 失败时仍生成结构完整、证据诚实的中文回退报告。
- 中栏成为实时过程到最终报告的连续主区域，持久化历史报告也在相同位置恢复。
- 报告标题、表格、列表、分隔线在桌面和移动端保持可读。

**Non-Goals:**

- 不改变 Planner、Executor、Replanner 的流程和工具选择。
- 不改变 SSE `report` 事件或证据链 API 数据结构。
- 不新增富文本编辑器、报告编辑或导出功能。

## Decisions

- Report 节点调用同一 `LlmProvider` 的 ChatModel，并要求仅返回 Markdown。相比前端二次格式化，后端生成并持久化最终文本可保证 SSE、历史查询和案例库使用同一份报告。
- 将项目 LLM 请求超时调整为 120 秒，避免长上下文 Planner 和 Report 在 Qwen 正常生成过程中连续触发 30 秒读超时；仍使用现有 Provider 重试配置。
- Prompt 固定章节顺序：活跃告警清单、每个告警的根因分析、处理方案执行、结论。输入数据以 JSON 附在 Prompt 后，要求缺失字段填“未获取”或“证据不足”，工具失败必须显式记录。
- 对模型响应移除可能包裹全文的 Markdown 代码围栏；空响应、调用异常或明显 JSON 响应使用确定性中文回退报告。
- 新建 `AiopsReportPanel` 作为中栏正式报告视图。报告生成前显示等待/执行状态，完成后读取持久化 `evidenceChain.reports` 的最新报告；实时 `report` 事件只用于在持久化数据回载前即时显示。
- 右栏 `AiopsEvidenceChain` 只展示报告来源摘要、证据 ID、证据载荷和工具调用，不重复正文。
- `MarkdownContent` 增加 `report` 展示模式，使用语义标题层级、受控正文宽度、表格滚动容器效果和打印文档式留白；不改变聊天消息的紧凑样式。

## Risks / Trade-offs

- [LLM 仍可能输出模板外内容] -> 强化 Prompt、剥离代码围栏，并用结构测试锁定关键标题；不尝试用脆弱的字符串重排模型内容。
- [模型异常时单次等待时间变长] -> 前端持续显示执行阶段和报告生成状态，最终仍使用本地回退报告收敛任务。
- [报告生成增加一次模型调用和延迟] -> Report 状态明确显示“正在生成报告”，调用失败立即使用本地回退，不阻断持久化。
- [表格在窄屏过宽] -> 仅表格自身横向滚动，页面和中栏不发生水平溢出。
- [旧报告仍是英文旧格式] -> 新展示兼容任意 Markdown；只对新诊断使用新 Prompt，不迁移历史内容。

## Migration Plan

无需数据库迁移。部署后新诊断使用新报告生成流程；回滚只需恢复 Report 生成函数和中栏组件，已有报告记录保持可读。
