## Why

聊天会话目前仅部分暴露：后端可以创建一个作用域内的会话记录，但user无法列出会话、通过API保留user和助手消息、查看历史记录、清除/删除会话，或依赖前端从SQLite重新加载聊天状态。此更改将聊天记忆转变为由已为记忆持久化建立的仓库边界支持的第一类经过身份验证的工作流程。

## 什么更改

- 添加完整的聊天会话管理 APIs 以创建会话、按逆序更新顺序列出会话、读取带有消息历史的会话、追加 user 和助手消息、清除历史记录以及删除会话。  
- 通过仓库接口将聊天会话和消息存储在 SQLite 中；前端状态可以缓存 UI 快照，但必须从后端 APIs 重新加载会话数据。  
- 从显式标题或第一个保存的 user 消息生成确定性的初始标题。  
- 保留结构化消息元数据，用于工具调用记录和知识库引用参考，以便后续的代理工作流可以将证据与聊天回合相关联。  
- 在所有会话和消息操作中强制执行当前的 user ownership，并对未认证或跨 tenant 访问返回统一的认证/授权错误格式。  
- 从 `packages/api-contracts` 导出共享的聊天 DTO 和 OpenAPI 路径，然后从前端代码中使用这些 DTO。

## 功能

### 新功能
- `chat-sessions`: 已认证的聊天会话和消息生命周期，前端会话状态，标题生成以及引用/工具元数据关联。

### 修改后的功能
- `api-and-sse-contracts`: 添加共享聊天会话/消息 DTO、请求/响应契约，以及针对列表/详细信息/消息/清除/删除操作的 OpenAPI 覆盖。
- `memory-repositories`: 在保持现有查询边界的同时，扩展聊天仓库契约以支持标题更新、会话删除和作用域内的消息清除。
- `authorization-and-tenant-isolation`: 明确所有聊天会话列表、历史记录、变更、清除和删除操作均为 tenant-作用域。

## 影响

- 后端：`apps/backend/src/super_ai/api/app.py`，内存仓库协议/SQLite 实现，以及后端 API/仓库测试。
- 前端：已认证的受保护数据客户端/state 和工作区聊天面板。
- 合同：`packages/api-contracts` 聊天 DTOs 和 OpenAPI 定义。
- OpenSpec: 新增 `chat-sessions` 规范，以及共享合约、内存仓库和授权的差异。
