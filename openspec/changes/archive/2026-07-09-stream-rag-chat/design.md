## 上下文

仓库已经具有经过身份验证的聊天会话，SQLite 支持的消息持久化，共享的 API/SSE 合同，一个 Qwen `ChatOpenAI` 提供者抽象，Milvus 支持的知识检索，以及前端聊天面板。缺失的部分是运行时聊天流程：user 消息必须由一个 Agent 来处理，该处理程序可以决定是否调用工具，通过共享的 SSE 事件合同流式传输其答案，并将完整的对话保存到 SQLite。

该功能涵盖后端 API、Agent 编排、LangChain 工具适配器、共享契约以及前端流式消费。必须保留 tenant 边界，避免使用供应商私有的 Qwen API，并在模块导入期间避免连接到 LLMs、Milvus 或 SQLite。

## Goals / Non-Goals

**目标：**
- 为聊天消息流添加一个经过身份验证的 SSE 端点。
- 使用配置的 Qwen `ChatOpenAI` 提供商和 LangChain 工具的 LangChain `create_agent`。
- 将现有的 tenant 范围内的知识检索功能作为 Agent 工具公开。
- 为工具生命周期、令牌增量、引用、完成和错误发出共享的 SSE 事件。
- 通过聊天仓库保留 user 消息和最终助手消息，包括引用和工具调用元数据。
- 更新前端聊天状态以消费流事件，并停止将追加消息 REST 调用作为主要的聊天发送路径。

**非目标：**
- 不为普通聊天引入自定义 LangGraph 状态图。
- 此次更改中不实现 AIOps 诊断流。
- 不添加内置的文档上传或索引自动化功能。
- 测试中不进行实际的网络调用。

## 决策

1. **在 FastAPI 后使用专用的聊天代理服务。** API 层将进行身份验证、验证会话、持久化 user 消息，并将流式传输委托给生成合同形状事件的服务。这可以使端点代码保持简洁，并使测试能够注入虚假的 Agent 运行器。

2. **将知识检索封装为一个LangChain工具，而不是固定的预步骤。** Agent 接收检索工具并决定是否调用它。包装器在请求时绑定当前user ID和可访问的知识库ID，因此模型提供的过滤器无法逃逸tenant的作用域。

3. **仅流式传输共享事件有效负载。** 后端将序列化与共享契约（`content.delta`、`tool.call`、`reference.source`、`complete`、`error`）匹配的事件名称的 SSE 帧。前端解析器将处理这些事件名称，并在刷新/保存会话历史记录之前更新瞬态流式状态。

4. **在生成完成后保留最终消息。** 在流式传输开始前，会写入user消息。助手消息由流式传输的增量组成，并在生成完成后写入，其中包含引用参考和工具调用ID的元数据。如果在user消息被保留后生成失败，流会发出共享错误事件，并且不会写入部分的助手消息。

5. **通过注入的假对象保持测试的确定性。** 测试将涵盖SSE序列化、持久化副作用、工具调用/引用事件处理以及前端解析，而不会调用Qwen、Milvus或外部服务。

## Risks / Trade-offs

- [风险] LangChain 流式事件的形状可能因版本而异。 -> 缓解措施：在 LangChain 运行器边界后隔离 LangChain 特定的解析，并使用假运行器事件测试服务行为。
- [风险] 在 user 消息被持久化后，长流可能会失败。 -> 缓解措施：发出一个共享错误事件，仅保留 user 消息的历史记录，并让 user 在同一会话中重试。
- [风险] 工具输出可能很大。 -> 缓解措施：发出结构化的引用事件并持久化引用元数据，而不是在聊天消息元数据中保存整个原始工具输出块。
- [风险] 流式传输期间前端状态可能不同步。 -> 缓解措施：将后端响应流视为助手草稿的权威来源，然后在完成之后从后端刷新/读取会话。

## 迁移计划

1. 添加共享流式聊天契约和 OpenAPI 路径定义。
2. 添加后端 Agent 运行器/service 和 SSE 端点，同时保持会话管理 APIs 完整。
3. 更新前端聊天发送流程以调用流式处理端点。
4. 验证后端、前端、合约和 OpenSpec 检查。
5. 在同步规范后归档更改。

回滚是代码回退：现有的聊天会话 CRUD 保持不变，此更改不需要模式迁移。

## 开放问题

没有开放的产品问题。实现可以适应本地 LangChain 环境中可用的 API 包，同时保留指定的服务边界。
