## 上下文

Vue 前端目前挂载了一个组件，该组件结合了身份验证、文档管理、聊天会话处理和占位符 AIOps 标签。现有的可组合样式客户端已经使用共享的合约类型，但应用程序没有路由边界、没有可重用的全局请求反馈，也没有一致的响应式工作区。后端通过 `packages/api-contracts` 暴露经过身份验证的 API 和类型化的 SSE 事件有效负载。

## Goals / Non-Goals

**目标：**

- 提供公共的登录和注册路由，以及用于聊天、知识和AIOps的受保护工作区路由。
- 构建一个响应式的产品工作区，在桌面端使用侧边栏，在小屏幕上使用图标优先的底部栏。
- 为HTTP和SSE建立一个单一类型的传输边界，由共享的API-合约包支持。
- 使认证和临时请求反馈成为反应式应用状态，同时在重新加载时仅保留承载令牌。
- 为后续的功能更改提供稳定的布局插槽和路由级别的加载、错误和空状态。

**非目标：**

- 交付聊天记录、文档工作流、AIOps 工作流、警报列表或引用详细信息体验。这些都是独立的功能更改。
- 更改后端 API 或 SSE 语义。
- 对聊天、文档、诊断或其他领域数据使用本地存储。

## 决策

### 为应用边界使用 Vue 路由器和 Pinia

shell 会为路由元数据和导航守卫添加 `vue-router`，并使用 Pinia 作为根级别的身份验证和反馈存储。这将替换 `App.vue` 中的手动条件渲染，同时保留现有的类型化身份验证客户端行为。路由器会将匿名 user 重定向到 `/login`，并带有预期的目标地址，同时将已认证的 user 从公共身份验证路由中重定向出去。

考虑过的替代方案：

- 继续使用条件渲染：被拒绝，因为无法可靠地建模视图生命周期和深度链接。  
- 添加更大的状态框架或自定义事件总线：被拒绝，因为Pinia是一个与更小表面积适配的原生Vue。

### 在类型客户端后集中传输

`apiClient` 将拥有请求头、承载令牌注入、JSON 封装解码和标准化的 API 错误。`sseClient` 将把服务器流解析为共享的 `SseEvent` 联合类型。特性客户端将调用这些边界，而不是构造 `fetch` 请求或本地解析事件字符串。

考虑过的替代方案：

- 保持端点特定的获取逻辑：被拒绝，因为错误处理和授权偏差在即将推出的接口中可能已经存在。
- 将EventSource视为唯一的流机制：被拒绝，因为经过身份验证的POST SSE流需要请求体和承载头。

### 将 shell 设为布局，而不是卡片序列

已认证的布局将具有持久化的导航栏、紧凑的顶部栏和路由内容出口。它将使用熟悉的 Lucide 图标、克制的边框、清晰的焦点处理和响应式的 CSS 网格规则。公开的身份验证视图会保持有意的专注，并且不会继承工作区的 chrome。

### 保持狭窄的持久化边界

认证存储会恢复承载令牌并通过 `/auth/me` 重新验证；所有其他屏幕状态从 API 加载。请求反馈在内存中是短暂的，并在适当的时候通过显式关闭或导航后清除。

## Risks / Trade-offs

- [Router 和 Pinia 添加构建依赖项] → 在工作区包中锁定它们，并使用 Vite 覆盖路由/认证行为。  
- [之前的全功能页面包含可工作的临时流程] → 保留其低级类型客户端，并仅将组合逻辑移动到路由视图；后续更改会刻意替换每个功能视图。  
- [SSE 有效负载可能格式错误或被中断] → 使用标准化的类型 API 错误来终止流，而不是暴露原始解析异常。  
- [响应式导航可能会隐藏当前上下文] → 使用路由派生的活动状态，在桌面使用文本标签，在移动设备使用带图标的标签，并使用可访问的 aria 标签。

## 迁移计划

1. 添加路由器、Pinia 和图标依赖项。
2. 引入通用传输、状态、路由器和反馈原语，并带有单元测试。
3. 用公共/authenticated路由组合和保留现有数据访问边界的安全占位符替换根组件。
4. 对本地启动的 API 进行类型检查、前端测试、生产构建以及已认证浏览器导航的验证。
5. 回滚操作包括撤销此仅前端的提交；不会发生后端迁移或持久化领域数据转换。
