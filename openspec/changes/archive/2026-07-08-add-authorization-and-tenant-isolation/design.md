## 上下文

后端现在对 user 进行身份验证并保护多个占位符数据端点，但内存记录和存储库方法仍然是全局作用域的。一旦知识库、向量检索、聊天和 AIOps 数据变为真实数据，全局查询将允许意外的跨 user 读取，除非 tenant 作用域是持久化边界的组成部分。

当前代码库对于内存数据有清晰的仓库协议，以及一个 FastAPI 身份验证依赖项，该依赖项解决了当前的 user。此更改应扩展这些现有的边界，而不是引入并行的身份验证框架。

## Goals / Non-Goals

**目标：**

- 将经过身份验证的 user ID 视为所拥有数据的 tenant 范围。
- 在聊天会话、聊天消息、AIOps 诊断任务、报告、工具调用审计、图 checkpoint 以及未来知识/向量元数据上保留 owner 范围。
- 要求仓库方法接收 `owner_user_id` 以进行范围内的读写操作。
- 当调用者访问其范围之外的数据时，返回统一的授权错误。
- 在存在向量存储实现之前，定义 Milvus chunk 元数据和检索过滤器要求。
- 在经过身份验证的 API 客户端和当前 user 状态之后，保持前端数据访问。

**非目标：**

- 无组织/team RBAC 模型。
- 无角色层级、管理员覆盖、ACL 共享或公共知识库模式。
- 此次更改中未实现完整的 Milvus 服务。
- 未迁移生产数据；该项目仍处于本地基础状态。

## 决策

### 用户 ID 是 tenant 的 ID

所有数据使用 `owner_user_id` 而不是引入单独的 tenant 表。这保持了当前单一 user 账户的产品模型简单，同时仍然使每个仓库查询显式作用域化。未来的组织模型可以在相同的仓库边界后引入单独的 tenant ID。

考虑的替代方案：现在添加一个 tenant 表。这会在产品有组织需求之前添加生命周期和成员决策。

### 范围属于仓库签名和索引

用于作用域数据的仓库创建/列出/获取方法接受 `owner_user_id`，并且 SQLite 查询会根据它进行过滤。记录还公开 `owner_user_id`，以便测试和调用者可以验证作用域传播。复合索引将 owner 作用域与资源 ID 和时间戳配对，当查询需要两者时使用。

考虑的替代方案：让 API 处理器过滤返回的数据。这会使业务代码可以意外调用未作用域的仓库方法。

### 禁止访问使用共享的 auth-category 403 错误

无效或缺失的令牌仍会以 `AUTH_UNAUTHENTICATED` 和 HTTP 401 响应。已知的经过身份验证的 user 请求超出其作用域的数据时，会收到 `AUTH_FORBIDDEN` 和 HTTP 403 响应，通过相同的响应封装。

考虑的替代方案：对于每个未授权的 id 返回未找到。这在以后可用于信息隐藏，但当前需求明确要求统一的权限错误。

### 向量 ownership 是以合同为先

Milvus 尚未實現，因此此更改定義了共享元數據和過濾器幫助程序，而不是添加供應商集成。塊元數據必須包含 owner/user/tenant 字段，檢索工具必須從當前 tenant 範圍中構建過濾器。

考虑的替代方案：等待Milvus集成。这将允许早期检索代码生成无作用域的元数据结构。

### 前端保持 API 作用域

前端不会在user之间本地保存或合并数据。它会在注销时清除持久化的身份验证状态，并通过使用当前持有者令牌的已认证客户端加载受保护的数据。这保持了UI隔离与后端强制的一致性。

## Risks / Trade-offs

- 现有的本地 SQLite 数据库缺少新的 owner 列 -> Alembic 迁移为当前开发数据添加了可为空的安全默认值，并验证了新数据库的迁移。
- 仓库签名更改会影响测试和未来的调用者 -> 协议强制编译时或类型检查反馈，而不是静默的全局访问。
- 用户 ID 作为 tenant ID 可能在以后太窄 -> 命名使用 `owner_user_id` 和 tenant 元数据辅助函数，以便在边界后引入组织 tenant。
- Milvus 过滤目前仅限于合约/辅助级别 -> 测试覆盖元数据/过滤器构建，未来检索实现必须使用这些辅助函数。

## 迁移计划

1. 为 owner 列和作用域索引添加 Alembic 迁移。
2. 更新 SQLAlchemy 模型和仓库数据类 /protocols.
3. 更新 SQLite 仓库实现，以按 `owner_user_id` 要求并进行过滤。
4. 添加共享授权错误和 OpenAPI 403 响应。
5. 添加后端受保护端点行为，返回所有者占位符数据并拒绝跨 owner 访问。
6. 添加向量元数据/filter 辅助合约。
7. 更新前端身份验证数据客户端/state 测试。
8. 验证、同步规范并归档。

回滚是对本地 SQLite 数据的正常迁移降级，同时在同一个提交中恢复仓库签名更改。

## 开放问题

没有阻塞的开放问题。组织 tenants、基于角色的访问、共享和公共数据被有意推迟。
