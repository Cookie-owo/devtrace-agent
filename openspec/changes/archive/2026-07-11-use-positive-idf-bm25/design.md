## Context

混合检索使用 `rank-bm25` 的 `BM25Okapi` 对请求内 tenant 语料排序。该实现的 IDF 为 `log(N-df+0.5)-log(df+0.5)`，高频词会得到负 IDF，并被替换为平均 IDF 的 epsilon 倍；当平均 IDF 也为负时，最终分数仍为负。真实端到端验证在仅有少量 chunks 的知识库中得到 `bm25Score=-7.376`。

RRF 只使用排名，因此负分不会破坏 RRF 公式，但负贡献可能让包含更多查询词的文档排名更低，也让前端分数难以解释。

## Goals / Non-Goals

**Goals:**

- 使用正 IDF 的成熟 BM25 变体，保证有词项命中的候选分数非负。
- 保持未命中词项贡献为 0，精确错误码和中英文词项继续参与排序。
- 保持现有双路并行、RRF 和 rerank 行为不变。

**Non-Goals:**

- 不修改中文分词策略、停用词或内存索引生命周期。
- 不归一化 BM25 分数，也不把它作为跨请求可比较的百分比。
- 不调整 RRF 的 `k=60` 或候选数量。

## Decisions

### 使用 `BM25L` 替换 `BM25Okapi`

`BM25L` 的 IDF 为 `log(N+1)-log(df+0.5)`。因为 `df <= N`，该值始终为正；其打分公式仍将未命中词项乘以词频 0，因此不会给无词项交集的文档增加基线分。

没有选择直接将 Okapi IDF 截断为 0，因为高频但有区分价值的词项会完全失去贡献。没有选择 `BM25Plus`，因为其 delta 项会让 query 中存在于语料的词对未命中该词的文档也产生基线贡献，与当前只按真实词项重合召回的语义不够一致。

### 保持 BM25 原始分只用于可解释性

RRF 继续只读取 BM25 排名，不直接混合 BM25 数值。前端继续显示原始 `bm25Score`，但它表示单次语料中的相对关键词相关度，不表示百分比，也不用于跨请求阈值。

## Risks / Trade-offs

- [更换 BM25 变体会改变同分候选的局部顺序] → 用小语料、高频词和精确错误码测试固定期望，并由 rerank 决定最终排序。
- [BM25L 分数仍受语料规模影响] → 明确其仅用于当前请求内排序与解释，不做跨请求比较。
- [这不解决每次请求重建内存索引的性能问题] → 保持本次变更聚焦，性能优化另行提案。

## Migration Plan

1. 修改 scorer 工厂并增加回归测试。
2. 运行全量后端、前端、契约与 OpenSpec 检查。
3. 使用现有前端测试文档重新检索，确认 BM25 分数为正且引用内容不回归。
4. 回滚只需恢复 scorer 类型，无数据迁移。
