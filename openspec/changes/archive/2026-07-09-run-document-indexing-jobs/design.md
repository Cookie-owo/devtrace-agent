## 上下文

仓库已经具备经过身份验证的文档上传、tenant 范围的文档元数据、SQLite 中的 OpenAI-compatible Qwen 模型配置，以及 Milvus 向量存储边界。上传的文档当前保持在元数据/索引状态 `pending`；没有作业记录、chunk 生成、嵌入调用、向量插入、重试路径或前端操作来重建索引。

实现必须在启动时不索引内置文档。索引是一个 user 触发的受保护工作流，必须保留与文档上传/删除相同的 tenant 隔离规则。

## Goals / Non-Goals

**目标：**
- 在 SQLite 中保留文档索引任务状态，包括 `pending`、`running`、`succeeded` 和 `failed` 状态以及失败原因和重试链接。
- 将上传的文档文本分块，调用配置的 OpenAI-compatible 嵌入模型，并将 tenant 拥有的 chunk 写入 Milvus。
- 暴露受保护的 API 和前端控件，用于手动文档重新索引和状态可见性。
- 将索引操作隐藏在仓库/提供者抽象层之后，以便业务代码不依赖于 SQLite 表、SQL 细节、DashScope SDK 或 Milvus 实现细节，超出向量存储边界。
- 从API安排索引而不阻塞后端请求/response周期。

**非目标：**
- 不支持启动时的文档摄入或捆绑文件的自动索引。
- 不支持完整的 PDF/OCR 解析器；首次实现将对使用文档元数据存储的 UTF-8 可解码上传内容进行索引。
- 不支持分布式工作队列。首个工作进程使用 FastAPI 后台任务，而仓库/任务边界为后续使用 Celery、Dramatiq 或服务工作进程留有空间。
- 除了存储范围向量外，无检索/rerank功能更改。

## 决策

1. **在专用存储库中持久化任务状态。**
   文档记录保留最新的 `index_status`，而 `document_index_tasks` 记录保存每次尝试的历史记录、状态、失败原因、时间戳和可选的重试源。这避免了文档元数据的过载，并为 UI 提供了一个稳定的任务状态资源。另一种方法是在文档上仅存储最新状态，但这样会丢失失败/重试的审计历史。

2. **通过可注入的服务运行索引。**
   `DocumentIndexingService` 接收仓库、嵌入提供者和向量存储。它负责 chunking、状态转换、向量写入和失败捕获。FastAPI 创建一个任务，然后在 `BackgroundTasks` 中安排该服务。另一种方法是在路由中直接执行工作；这会阻塞响应，并使重试更难测试。

3. **通过现有的LLM提供者边界使用OpenAI-compatible嵌入。**
   添加一个由`langchain-openai`嵌入和配置的`embedding_model`支持的嵌入协议/factory。业务代码依赖于该协议。这遵循现有的Qwen OpenAI-compatible设计，并避免了DashScope SDK耦合。

4. **将文本源暂时存储在文档元数据中。**
   上传操作会将 UTF-8 解码后的文档文本保存在元数据中，这样索引器可以在不使用单独对象存储的情况下重新构建 chunk。这对于当前的 10 MB 上传限制和现有的 SQLite 基础来说是可以接受的。以后可以添加对象存储功能，用基于仓库的二进制大对象指针替换此功能，而无需更改索引服务合同。

5. **在重新索引之前替换文档 chunk。**
   每次运行都会删除该文档的现有作用域 chunk、chunk 当前文本、嵌入内容，并插入一批新的。这使得手动重建变得确定性。另一种方法是差异 chunk 更新，但在存在版本化文档内容之前这是不必要的。

## Risks / Trade-offs

- **SQLite元数据中的大文档文本** -> 保持现有的上传限制，仅存储用于MVP索引所需的解码文本，并保持存储访问权限在仓库记录之后，以便对象存储以后可以替换它。
- **BackgroundTasks仅限于进程内** -> 在调度之前保存作业状态，并在SQLite中标记失败；未来的工作者系统可以使用相同的仓库边界来获取`pending`作业。
- **Embedding提供者/网络故障** -> 捕获安全的失败消息，将任务/文档标记为`failed`，并让users手动重试。
- **PDF内容可能无法干净地解码** -> 将无法解码的二进制文本视为验证/索引失败；在此更改中不要引入重型解析依赖项。
- **Milvus部分写入** -> 在插入前删除现有的作用域chunks，并在向量插入引发异常时标记任务失败，使状态可见以便重试。

## 迁移计划

1. 为`document_index_tasks`添加Alembic迁移，包含owner、知识库、文档、状态、时间戳、失败原因、重试来源和作用域索引。
2. 扩展仓库协议和SQLite实现，用于创建、读取、列出、转换和重试索引任务。
3. 首先添加嵌入提供者和索引服务测试，然后实现。
4. 添加受保护的API路由和共享契约。
5. 添加前端客户端/state/UI 控制项，用于手动重建和状态刷新。
6. 验证 OpenSpec，后端测试/类型检查/静态分析，合约测试/类型检查，前端测试/构建。

回滚通过保留未使用的表和停用路由来保持模式兼容性。如果未调用后台索引，则现有的文档上传/list/delete行为仍然可用。

## 开放问题

- 未来更改应决定当上传文件超过 SQLite 元数据的舒适区域时，原始文档字节应存储在哪里。
- 未来更改应决定当部署使用多个后端副本时，索引任务是否需要分布式工作线程租约/心跳。
