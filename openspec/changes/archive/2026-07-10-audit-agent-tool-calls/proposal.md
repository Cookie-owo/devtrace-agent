## Why

聊天 Agent 已经会发出实时工具生命周期事件，但这些事件在流结束后就会消失。操作员和最终 user 无法检查工具接收到的内容、是否成功、耗时多久，或者在审查对话或诊断任务时其结果的安全摘要。

## 什么更改

- 每次 Agent 工具调用都作为 tenant 范围内的 SQLite 审计记录进行持久化，包括其输入、生命周期状态、结果摘要、错误和耗时。
- 允许审计记录属于聊天会话或 AIOps 诊断任务，仓库操作将强制父资源的 owner 范围。
- 记录聊天 Agent 工具生命周期事件而不延迟现有的 SSE 流，并通过经过身份验证的 API 暴露持久化的聊天会话审计追踪。
- 扩展共享的 API 合同和前端状态，使聊天会话能够可见地显示工具调用及其最终摘要，包括页面刷新后。

## 功能

### 新功能

- `agent-tool-call-audits`: 租户范围的持久化、检索、API 合同以及 Agent 工具调用审核的聊天 UI。

### 修改的功能

- `memory-repositories`: 扩展仓库边界和 SQLite 模式，以持久化聊天会话以及 AIOps 任务的工具审核信息。
- `stream-rag-chat`: 持久化代理工具生命周期事件，并在流式传输过程中显示其审核标识符。
- `api-and-sse-contracts`: 为聊天工具调用审计历史定义共享的 HTTP 资源形状。

## 影响

- 受影响的后端区域：SQLAlchemy 模型，Alembic 迁移，仓库协议和 SQLite 实现，聊天流服务，以及 FastAPI 路由。
- 受影响的前端区域：共享的 TypeScript 合同，受保护的数据客户端和状态，以及聊天会话详细渲染。
- 受影响的存储：SQLite 增加了一个通用的 `tool_call_audits` 表，而现有的旧版诊断审核数据保持不变。
