# API 排障

## 目标

对 API 超时、错误率升高、返回码异常和依赖失败进行证据驱动的分层排查。

## 排查顺序

1. 确认接口、环境、时间范围和影响用户。
2. 检查状态码、延迟分位数和请求量变化。
3. 根据 request id 或 trace id 关联应用日志。
4. 检查上游和下游依赖的超时、重试与不可用记录。
5. 对照最近变更和已有 SOP，形成可验证假设。

## 约束

- 不把相关性直接描述为因果关系。
- 不建议未经验证的破坏性操作。
- 工具失败时保留失败信息并给出替代检查路径。
